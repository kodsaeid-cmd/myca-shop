# ارتقای پایگاه داده مایکا — نسخه Commerce Platform

**مهم:** دیتابیس مجله یا سرویس اصلی مایکا را دست‌کاری نکنید. ارتقا فقط روی MySQL مستقل فروشگاه انجام می‌شود.

1. از همان دیتابیس فروشگاه در cPanel / phpMyAdmin خروجی SQL کامل با جداول و اطلاعات بگیرید.
2. وجود جداول پنج‌گانه اولیه و پاسخ موفق `api/catalog.php` را کنترل کنید.
3. فایل `db/migrations/002_commerce_platform.sql` را در phpMyAdmin روی دیتابیس **فروشگاه** اجرا کنید؛ این فایل با `CREATE TABLE IF NOT EXISTS` جدول‌های جدید را ایجاد می‌کند. روی دیتابیس مجله اجرا نشود.
4. پس از اجرا، وجود `shop_customers`، `shop_carts`، `shop_order_items`، `shop_product_seo`، `shop_pages`، `shop_reviews` و سایر جدول‌های جدید را بررسی کنید.
5. قبل از هر تغییری در شاخه اصلی، فایل‌های جدید را روی محیط تست جداگانه کپی کنید؛ فایل `app/config.local.php` حاوی رمز را جایگزین نکنید.
6. در `app/config.local.php` فقط پس از HTTPS معتبر، تنظیمات زیر را در آرایه پیکربندی اضافه کنید (مقادیر پیش‌فرض امن‌اند):

```php
'public_base_url' => 'https://shop.mycablog.dandoonii.ir',
 'test_mode' => true,
 'enable_customer_auth' => false,
 'enable_checkout' => false,
 'enable_marketing' => false,
```

7. صفحه محصول را با مسیر `/product/<slug>/`، صفحه دسته با `/collection/<slug>/` و پیش‌نمایش CMS را با `/storefront.php` بررسی کنید.
8. برای حل ارث‌بری DirectoryIndex، فایل `admin/.htaccess` جدید را آپلود کنید. برای فعال‌کردن صفحه اصلی CMS، **فقط در `.htaccess` ریشه فروشگاه** و پس از بک‌آپ، دستور `DirectoryIndex index.php index.html` را با تنظیم فعلی ادغام کنید؛ فایل اصلی مجله را تغییر ندهید.
9. **از فعال‌کردن حساب مشتری و Checkout قبل از گواهی HTTPS معتبر و بررسی امنیتی خودداری کنید.** روی دامنه عمومی حتی حساب آزمایشی هم می‌تواند رهگیری شود. در نسخه تست، فقط API عمومی، سبد بدون اطلاعات هویتی و صفحه‌ساز را بررسی کنید.
10. درگاه پرداخت، پیامک و مرجوعی مالی به سرویس واقعی متصل نیستند. ابتدا ارائه‌دهنده و مدل تسویه را انتخاب و یکپارچگی را به‌صورت جداگانه تست کنید.

## Rollback

- کد: بازگشت به بک‌آپ `index.html`، اسکریپت‌ها و APIهای اسپرینت اول. فایل تنظیمات محرمانه باید حفظ شود.
- پایگاه داده: **هیچ جدول جدیدی را بدون بررسی حذف نکنید.** بازگشت اسکیمای داده باید از بک‌آپ SQL گرفته‌شده پیش از اجرا انجام شود. جداول اولیه عمداً در Migration 002 تغییر داده نشده‌اند.
- مجله: این Migration هیچ ارتباطی با دیتابیس مجله ندارد.
