# MYCA Shop — توسعه جامع ماژولار (سری Sprint 02–06)

> **وضعیت:** نسخه کد در شاخه توسعه؛ نه انتشار نهایی و نه پذیرش تجارت واقعی. همه ماژول‌ها از یک زیرساخت MySQL/PHP استفاده می‌کنند، ولی بخشی از قابلیت‌های بیرونی و عملیات مالی هنوز در حالت پیش‌نیاز/غیرفعال است.

## چه چیزهایی واقعاً کدنویسی شده‌اند؟

- Migration افزایشی: حساب مشتری، آدرس‌ها، تنوع SKU، رسانه و ویدیو، سئوی محصول، روابط محصولات، نظرات و پرسش‌ها، علاقه‌مندی، سبد سروری، سفارش و اقلام snapshot، تاریخچه سه‌محوره سفارش/پرداخت/ارسال، مرجوعی، تیکت، CMS و نسخه انتشار، کوپن، رویداد و outbox.
- صفحات سروررندر عمومی: محصول (`/product/{slug}/`)، دسته (`/collection/{slug}/`)، صفحه CMS (`/pages/index.php?slug=...`)، پیش‌نمایش خانه (`/storefront.php`). ساختار داده Product برای نسخه عملیاتی (در نسخه تست noindex) آماده شده است.
- APIهای محصول/جست‌وجو/سبد، پروفایل، نشانی، علاقه‌مندی، نظرات و پرسش‌ها، سفارش آزمایشی، تیکت و مرجوعی با کنترل‌های احراز هویت و CSRF.
- UI حساب مشتری (`/account/`)، سبد (`/cart/`)، تسویه (`/checkout/`) و راهنمای پیگیری (`/track/`).
- پنل افزوده ادمین (`/admin/commerce.php`) برای SEO، گالری ویدیو، تنوع، انتشار بلوک‌های صفحه اصلی، نظرات، سفارش و وضعیت ارسال، مرجوعی، مشتری، سبد رهاشده، کوپن و پشتیبانی.
- صفحه اصلی پویا از `index.php` پس از انتشار CMS؛ تا آن زمان **ویترین قبلی `index.html`** بدون دستکاری در ظاهر باقی می‌ماند. نسخه قدیمی در لینک‌ها به صفحات محصول و سبد سروری جدید هدایت می‌شود.
- اسکریپت CLI صف‌سازی کاندیداهای بازیابی سبد **بدون ارسال پیامک/ایمیل**؛ مرز سرویس پرداخت `app/payments.php` عمداً غیرعملیاتی است.

## هنوز تکمیل و تست نشده‌اند

- پرداخت بانکی، وبهوک مالی واقعی، تاییدیه پرداخت، ضدتکرار تراکنش/Idempotency انتهابه‌انتها، تسویه و بازپرداخت واقعی؛ *هیچ ادعای پرداخت موفق ساخته نمی‌شود*.
- ارسال پیامک و OTP، احراز مالکیت موبایل، یکپارچگی هویت اپلیکیشن مایکا، اتصال به شرکت حمل و رهگیری برخط، چاپ فاکتور رسمی، مالیات/ارسال منطقه‌ای، وفاداری و کمپین‌های خودکار.
- نسخه اول تخفیف را در پنل ذخیره می‌کند اما قوانین کوپن هنوز به quote نهایی متصل نشده‌اند؛ نسخه اول موجودی را هنگام سفارش آزمایشی رزرو/کسر نمی‌کند (عمداً).
- Analytics کامل قیف، ارسال بازیابی سبد از Outbox، صفحه‌ساز زمان‌بندی‌شده، ویرایش رسانه به‌صورت حرفه‌ای، تست پایگاه داده روی پارس‌پک، تست end-to-end مرورگر و تست نفوذ.
- محتوا و رسانه کالاهای نمونه واقعی نیستند و تا تکمیل نباید ایندکس شوند.

## کنترل دسترسی

- `enable_customer_auth=false` به‌صورت پیش‌فرض؛ برای ورود مشتری **HTTPS معتبر و تنظیمات صریح** لازم است.
- `enable_checkout=false`؛ حتی در صورت روشن‌کردن این گزینه تنها وقتی `test_mode=true` باشد ثبت **سفارش آزمایشی بدون پول، بدون کاهش موجودی و بدون فاکتور واقعی** انجام می‌شود.
- `enable_marketing=false`؛ هیچ پیامک یا ایمیل ارسال نمی‌شود. داده‌های رضایت بازاریابی باید ثبت شوند.
- API عملیات تجاری ادمین به حساب ادمین فعال و HTTPS نیاز دارد و عملیات پرداخت به‌طور صریح از مسیر ادمین قابل جعل نیست.
- جدول‌های قدیمی و صفحه اصلی قبلی حذف نمی‌شوند.

## نصب تستی

ابتدا `db/UPGRADE.md` را بخوانید. سپس برای آزمون محدود روی پارس‌پک فقط Migration افزایشی را روی دیتابیس **فروشگاه** اجرا کنید، فایل‌های جدید را به‌صورت کنترل‌شده Deploy کنید و URLهای عمومی را بررسی کنید. تنظیم `.htaccess` ریشه را بدون بک‌آپ تغییر ندهید.

تست محلی کد (بدون MySQL):

```bash
find . -name '*.php' -print0 | xargs -0 -n1 php -l
node --check assets/platform.js
node --check assets/platform-admin.js
php tests/platform-smoke.php
```

برای پذیرش نهایی لازم است DB MariaDB/MySQL واقعی و مرورگر تست در staging راه‌اندازی شوند. تست نحوی جای تست واقعی نیست.
